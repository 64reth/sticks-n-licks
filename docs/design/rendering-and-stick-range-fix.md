# Playable-scene launch rendering and stick-range correction

## Root causes, reproduced in the actual main scene

The configured entry remains the repository-root `project.godot` → `scenes/main/main.tscn`. No nested project, working copy or camera changes were needed. The viewport remains 320×180 with nearest-neighbour sprite filtering, and both fighter Node2D roots have unit scale.

The imported SpriteFrames use 768×768 padded native textures, each with an authored display scale and baseline in `data/animations/fighter_0N.json`. Assigning SpriteFrames automatically selected `idle`. `Fighter.pose` also started as `idle`, so the old early return in `set_pose("idle")` skipped applying the metadata entirely. A fresh playable-scene inspection printed **scale (1,1), position (0,-30), texture (768,768)** for both fighters. Their native-size artwork therefore overwhelmed the viewport. The animation preview immediately selected `character_master`, which applied its metadata and masked the launch-specific bug. Earlier media tests similarly changed poses before checking transforms.

`set_pose` now always applies the requested animation's metadata; only restarting playback is conditional on an actual animation change. Fresh main-scene idle scales are approximately **0.121212 Red / 0.280702 Blue**, derived from the supplied images' different native body heights, not arbitrary global shrink factors. Both display roughly 64-pixel standing bodies. Per-state scales, source-relative facing and ground anchors are retained through repeated calls and animation transitions. Parent/hurtbox scale stays one. No source or extracted image was resized, cropped, regenerated or overwritten.

Combat previously used a **140-pixel centre-distance cutoff**. The 120-pixel initial spacing was already inside that range, so attacks could land without approaching. The existing Area2D was not used in damage decisions and there was no common authoritative weapon overlap check. The enlarged initial visuals further disconnected apparent character size from logical spacing.

## Shared, configurable stick geometry

`stick_reach` in `data/combat/settings.json` defaults to **44 logical pixels**, measured from fighter anchor toward stick tip, shared by high, mid and low. Supplied impact silhouettes extend roughly 40–51 horizontal display pixels; one common reach avoids granting different ranges to artwork variants. This is an initial balance setting, not a height-specific statistic.

Each fighter has an attached named `Hurtbox` Area2D and CollisionShape2D, matching the deterministic gameplay rectangle: 18 pixels wide, 64 high, ending at ground y=150. It is kept at the authoritative logical position rather than following interpolated sprite drift. Collision layers are explicit; damage never depends on asynchronous physics overlap callbacks or on image dimensions.

Attack regions run from the body's forward edge (9 pixels) to the shared stick tip (44), with identical 12-pixel bands centred at high/mid/low body heights. `Bout.in_reach` uses the same rectangle-overlap function for all heights and both facing directions. Touching the hurtbox boundary counts as overlap: the default maximum centre gap is 44+9=53 pixels. At 53.001 pixels all heights whiff. Changing the single reach setting changes all heights together.

Positions are snapshotted at beat 4. Input combinations still use ±70 ms perfect / ±140 ms valid windows and the existing 100 ms combination buffer; adjudication still waits for that buffer to close within beat four. A valid late combination uses the same beat-four positions. Animation/sprite changes after impact cannot change the contact result. The attack region is active only during the valid beat-four action window, never during windup, movement or post-resolution recovery.

Range validation precedes block/parry logic. Out-of-range attacks always produce **WHIFF**, score no hit, add no defensive streak and pass initiative. In range, existing high/mid/low matching and timing decide **HIT / BLOCK / PARRY**. Both scene-level and Bout-level exchange guards prevent duplicate hit/initiative effects. Missing execution retains its existing miss/initiative consequence without playing a phantom attack. Attempted whiffs reuse the supplied attack's common recovery pose/tint; all heights share the same visual recovery duration and existing initiative penalty. No new per-height reach, damage or recovery properties were added.

## Debug display and verification

F3 draws geometry above the fighters: cyan hurtboxes, orange filled active attack regions, and a faint outline of the last evaluated region. The outcome is labelled LAST HIT/BLOCK/PARRY/WHIFF; the compact HUD retains beat/phrase, initiative, errors, queued movement, movement timestamps, recording/offset and latency/tempo diagnostics. No filled attack region means there is no currently active attack. A defender may animate an attempted guard at a distance; it does not register as a block or parry without incoming contact.

`tests/test_launch_range.gd` loads the actual configured main scene and checks the untouched initial menu **before selecting any pose**, then every available frame's display size, viewport bounds and ground anchors. It also exercises physical InputMap events, shared range boundaries, both attackers/all heights/all three BPMs, far good/perfect defence, advancement/retreat, beat-four snapshots, active windows and duplicate-adjudication guards. Full standoff/race/approach/three-hit victory/Enter-rematch loops complete for both winners.
