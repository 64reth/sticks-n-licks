## Project conventions

Develop directly in `/Users/garethwallen/Projects/sticks-n-licks`. Keep `project.godot` at the repository root and `run/main_scene` pointing to the playable `res://scenes/main/main.tscn`. Do not create a nested Godot project or a separate working copy. Preserve a working F5 launch throughout development.

Godot 4.6+, GDScript, 320×180 viewport, nearest-neighbour textures. 96×96 remains the target for newly authored art; supplied Milestone 002 art is preserved at native resolution in padded 768×768 RGBA frames, baseline 744, with per-animation display scale. Do not force these sources through the strict 96px AI-sheet validator. Use the Milestone 002 manifests/tests. Red is natively right-facing and Blue left-facing; mirror relative to source orientation exactly once. Use Godot InputMap; Right Shift is P2 execute/race, Down is P2 low, S is P1 low. Forward (derived from current facing) + execute is MID. Keep 100 ms bidirectional combination buffering, held-direction support, and inclusive ±70/±140 ms timing. Movement state lives in `CombatInput`: conductor beats 1–4 may step; use fresh taps only, at most one step per beat, PERFECT ±90 ms / GOOD ±160 ms; never repeat held movement. Movement is independent of combat precision windows and is not suppressed by an attack/block chord. At beat four, accept early/late movement and apply collision limits, close the movement window including latency compensation, freeze positions, then adjudicate buffered combat against that snapshot. Combat rules are in `scripts/combat/bout.gd`, the clock in `scripts/rhythm/rhythm_conductor.gd`, orchestration in `scripts/main.gd`. Production musical time is monotonic microseconds or the audio playback clock, never accumulated frame delta. The injected clock in the scripted demo is test-only.

Keep timing windows, input latency, race configuration and escalation thresholds in `data/combat/settings.json`; resource paths and beat-zero offsets in `data/audio.json`. Tempo transitions happen only at phrase boundaries. A race win or parry never awards a hit. Missing production assets must not block launching.

Store original character artwork under `source/` or `references/`; never destructively resize or overwrite it. Export validated frames into a new version directory and inspect the manifest before configuring the fighter. Automated pixel checks do not approve character identity or visual quality. Do not add an API key to Godot or game exports. The optional Python tools are development dependencies only.
