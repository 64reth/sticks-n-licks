## Project conventions

Develop directly in `/Users/garethwallen/Projects/sticks-n-licks`. Keep `project.godot` at the repository root and `run/main_scene` pointing to the playable `res://scenes/main/main.tscn`. Do not create a nested Godot project or a separate working copy. Preserve a working F5 launch throughout development.

Godot 4.6+, GDScript, 320×180 viewport, nearest-neighbour textures. 96×96 remains the target for newly authored art; supplied Milestone 002 art is preserved at native resolution in padded 768×768 RGBA frames, baseline 744, with per-animation display scale. Do not force these sources through the strict 96px AI-sheet validator. Use the Milestone 002 manifests/tests. Red is natively right-facing and Blue left-facing; mirror relative to source orientation exactly once. Use Godot InputMap; Right Shift is P2 execute/race, Down is P2 low, S is P1 low. Forward (derived from current facing) + execute is MID. Keep 100 ms bidirectional combination buffering, held-direction support, and inclusive ±70/±140 ms timing. Movement state lives in `CombatInput`: conductor beats 1–4 may step; require the direction to remain held and cancel on release. Movement is independent of combat precision windows and is not suppressed by an attack/block chord. At beat four, apply both movement steps/collision limits first, freeze positions second, then adjudicate buffered combat against that snapshot. Combat rules are in `scripts/combat/bout.gd`, the clock in `scripts/rhythm/rhythm_conductor.gd`, orchestration in `scripts/main.gd`. Production musical time is monotonic microseconds or the audio playback clock, never accumulated frame delta. The injected clock in the scripted demo is test-only.

Keep timing windows, input latency, race configuration and escalation thresholds in `data/combat/settings.json`; resource paths and beat-zero offsets in `data/audio.json`. Tempo transitions happen only at phrase boundaries. A race win or parry never awards a hit. Missing production assets must not block launching.

Store original character artwork under `source/` or `references/`; never destructively resize or overwrite it. Export validated frames into a new version directory and inspect the manifest before configuring the fighter. Automated pixel checks do not approve character identity or visual quality. Do not add an API key to Godot or game exports. The optional Python tools are development dependencies only.

Milestone 002 uses `tools/import_fighter_art.py` for the reviewed irregular-sheet extraction and `tools/catalogue_audio.py` for WAV metadata. Extraction refuses an existing output directory. Keep source hashes and derivative rectangles/translations in the manifests. Missing art remains explicitly labelled; no inferred frame may be called a new authored animation. Supplied soft alpha edges remain source pixels; any alpha-haze removal applies only to derivatives. The owner confirmed beat 1 at sample zero and full-file boundaries for the eight current recordings. Future audio beat-zero/loop fields must stay null until confirmed: preview playback and exact duration do not establish musical downbeats. Keep one music player, continuous unwrapped playback time and phrase-boundary transitions. Never couple combat resolution to animation completion.

Always apply visual metadata when selecting a pose, even if SpriteFrames already auto-selected that animation; only playback restart may be skipped. Test the configured main scene before any pose changes. Damage uses `Bout`'s beat-four logical hurtbox/attack-region overlap and a single configurable `stick_reach` for every height. Keep the attached hurtbox independent of sprite scale/interpolation. Out-of-range guards cannot block/parry; animation callbacks never award hits. Maintain both scene/rule exchange guards and run the launch/range regression suite through `tools/check.sh`.

Record physical direction presses/releases outside combat so countdown/pickup holds survive into the first eligible combat beat. Never carry pending race execute into combat. Keep release-before-boundary cancellation; movement is independent of attack timing windows. Start walking only after actual displacement and use per-fighter visual recovery deadlines. Maintain F3 input/step feedback. The current Blue idle update is in `frames/idle_002`, mapped to both `idle` and `combat_idle`; its four native frames duplicate supplied mid-block artwork. Do not regenerate Red assets to update Blue.

Milestone 003 is authoritative over earlier movement-lockout documents: all four beats permit movement; beat four additionally permits combat. Normal presentation is `ArcadeHUD` in a CanvasLayer; legacy raw labels/collision diagnostics are F3-only. Energy is computed from the opposing attacker's `Bout.hits`, never a second health field. `MatchProgress` awards one marker per three-hit round, default best-of-three (`match_best_of: 3`), two wins for champion. Enter advances a round or starts a rematch as appropriate. False-start/race retries reset the round's bout, never match markers. Countdown labels derive from the final three conductor beats and authoritative cue, with no independent countdown timer.
